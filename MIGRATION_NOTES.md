# Migration notes — env restructuring + auth moved to the backend

This documents what changed in this pass and, importantly, **what you still
need to do by hand in your actual Codespace** — I only had a sanitized zip
(no real secrets, no live DB, no network access to test), so none of this
has been run against a real database or in a browser.

## What changed in the code

### Backend (`apps/backend`) now owns all admin functionality
- `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout`
- `GET/POST /api/admin/projects`, `GET/PUT/DELETE /api/admin/projects/:id`
- `GET /api/admin/categories`
- `POST /api/admin/upload-image` (multipart via `multer`, new dependency)
- All protected by JWT (`requireAuth` middleware), signed with `AUTH_SECRET`
- `cors()` now reads `CORS_ORIGIN` from env instead of allowing every origin

### Frontend (`apps/web`) no longer touches auth, admin writes, or Cloudinary
- NextAuth is gone entirely (`auth.ts`, `lib/auth.ts`,
  `app/api/auth/`, and the `next-auth`/`bcryptjs`/`cloudinary`/`@vercel/blob`
  dependencies all removed)
- The old `app/api/admin/*` proxy routes are gone — the browser calls
  `apps/backend` directly via `lib/admin-client.ts`'s `adminFetch()`, which
  attaches the JWT from `localStorage` as `Authorization: Bearer <token>`
- `admin/page.tsx` and `admin/projects/page.tsx` changed from server
  components (direct Prisma calls) to client components that fetch from
  the backend
- Public pages (`work/`, `category/`, homepage) are **unchanged** — they
  still read MongoDB directly via Prisma in `apps/web/lib/projects.ts`;
  that was never part of the auth/secret duplication problem

### Env files: 3 → 2, and no more `prisma/.env`
- `prisma/seed.ts` now loads `apps/backend/.env.local` instead of a
  separate `prisma/.env` file
- `apps/web/.env.example` and `apps/backend/.env.example` replace the old
  single root `.env.example`

## Manual steps to do in your real Codespace

1. **Pull this code back down** (or apply the same changes) so it's not
   just sitting in this chat.
2. **Delete `prisma/.env`** if it exists — no longer read by anything.
3. **Rebuild your real env files** from the new examples:
   ```bash
   cp apps/web/.env.example apps/web/.env.local
   cp apps/backend/.env.example apps/backend/.env.local
   ```
   Then fill in real values. `apps/web/.env.local` should end up short —
   just `DATABASE_URL` and `NEXT_PUBLIC_BACKEND_URL`. Everything else
   (AUTH_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD_HASH, Cloudinary keys,
   BLOB_READ_WRITE_TOKEN) goes in `apps/backend/.env.local` only.
4. **Root `.env`** — I could not inspect or delete your real one (it was
   excluded from the zip you gave me and I have no filesystem access to
   your Codespace). It has `VERCEL_OIDC_TOKEN` in it, which is
   auto-generated by the Vercel CLI, not something you hand-maintain —
   check whether anything in your workflow still expects a root `.env`
   before deleting it; if it's purely leftover Vercel CLI output, it's
   safe to remove and will regenerate if you run `vercel env pull` again.
5. **`npm install`** at the repo root — the backend has a new dependency
   (`multer`) and `apps/web`'s dependency list shrank (`next-auth`,
   `bcryptjs`, `cloudinary`, `@vercel/blob` removed). Consider
   `rm -rf node_modules package-lock.json && npm install` to be safe.
6. **Smoke-test the whole flow**, since none of this has been run:
   - `npm run dev` (both servers) → visit `/admin/login`
   - Log in with your admin email/password
   - Confirm the dashboard loads (`GET /api/auth/me` should resolve)
   - Try creating a project, uploading a cover image, editing, deleting
   - Check the browser console/network tab for CORS errors — if you see
     them, double check `CORS_ORIGIN` in `apps/backend/.env.local` matches
     the frontend's actual origin exactly (scheme + host + port)
7. **Tests**: `apps/web/__tests__/setup.ts` and its MSW mocks may still
   reference the old NextAuth/proxy-route setup — not yet updated in this
   pass. Expect some test failures until those mocks are updated to match
   the new backend-based auth.
